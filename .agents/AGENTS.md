# AGENTS.md

Guidance for AI coding agents working with this dotfiles repository.

## Installation

```bash
./install          # Bootstrap everything: submodules, symlinks, Homebrew, npm, macOS setup
```

`install` is a thin bash wrapper around [Dotbot](https://github.com/anishathalye/dotbot). It syncs/updates the `dotbot` submodule, caches sudo up front (`sudo -v` plus a 60s keepalive loop, so the `shell:` steps never prompt mid-run), then runs `dotbot/bin/dotbot -d . -c install.conf.yaml "$@"` — extra arguments are forwarded (e.g. `./install --only=link`).

`install.conf.yaml` is the single source of truth for what lands where:

- **`defaults`** — link ops `create`/`relink`/`force`/`backup` plus `relative: true`; `clean` runs over `~` and `~/.config`, so links removed from the config are pruned on the next run (and conflicting files are backed up).
- **`link`** — `home/…` → `~` / `~/.config/…`. Most entries are single files, and that mapping exists *only* here (`home/lazygit.yml` → `~/.config/lazygit/config.yml`, `home/agignore` → `~/.rgignore` + `~/.fdignore` + `~/.ignore`). Two exceptions: `~/.zsh` links the whole `home/zsh/` directory, and `~/.config/nvim/` links every child of `home/vim/*` via `glob: true`.
- **`install-brew` + `brewfile`** — installs Homebrew if missing, then runs `brew bundle` against this repo's `Brewfile`.
- **`shell`** — `touch ~/.hushlogin`, `touch ~/.rm_recycle`, `scripts/macos/dockutil_init.sh`, `scripts/macos/hide_folders.sh`, SSH dir/key permission fixes.
- **`duti`** — default app associations from `scripts/macos/Dutifile`.

Dotbot plugins are git submodules in `dotbot-plugins/`: `dotbot-brew` (third-party; supplies the `brew`/`brewfile` directives) and `dotbot-duti` (supplies `duti`). Update with `git submodule update --init --recursive`.

**No tests, no lint, no application code.** The only "builds" are re-running `./install` (idempotent), `home/karabiner` (`bun index.ts` — rewrites Karabiner's live config) and `home/hammerspoon` (`npm run bundle` — esbuild). Lint configs that *live* here (`home/luaformatter.yaml`, `home/vale.ini`) configure other tools — they aren't run from this repo.

## Key architecture notes

**Private config via iCloud:** SSH keys, GPG, work gitconfig, and other secrets live at `~/iCloud/Internal/private/` (outside this repo). Dotbot symlinks `home/zsh/private` → that path on macOS at install time; the symlink isn't committed and won't appear in `git ls-files` (only `.keep` is kept, via a `.gitignore` exception). Additional private symlinks: `~/.ssh` (`…/private/ssh`), `~/.gnupg` (`…/private/gnupg`), `~/.gitconfig.local`, `~/.agents` (`…/private/agents/`), `~/.claude` (`…/private/claude/`), `~/.config/opencode`, `~/.omp/agent/config.yml`.

**Global gitignore doubles as repo policy:** `home/gitconfig` sets `core.excludesfile = ~/code/dotfiles/home/gitignore_global`, so that file (installed at `~/.gitignore_global`) applies to every repo on the machine. Patterns like `.claude`, `/.bundle/`, `Gemfile.local`, `sandboxes`, `logs` are therefore ignored here *without* appearing in this repo's `.gitignore` — check it before assuming an untracked file should be added.

**`$DOTFILES` env var is load-bearing.** `home/zshenv` exports `DOTFILES=$HOME/code/dotfiles` (plus `HOME_DIR`, `XDG_CONFIG_HOME`, `LANG`/`LC_ALL`, `PAGER`/`LESS`, `skip_global_compinit`) so it exists in every zsh, including `zsh -c`; `zshrc` sources every split file via `$DOTFILES/home/zsh/...`. Tool config lives in `home/zprofile`: `HOMEBREW_*` (incl. `HOMEBREW_BUNDLE_FILE_PATH`, pinned to this repo's Brewfile so ad-hoc `brew bundle` uses it), `BAT_CONFIG_PATH`, `RIPGREP_CONFIG_PATH`, `BOB_CONFIG` (`~/.config/bob/config.json`), `NAVI_PATH` (points at `$DOTFILES/home/doc`, which is not present in this checkout), compiler flags, `PRIVATE_FILE` (`~/.zsh/private/private.zsh`). PATH is rebuilt there in a guarded `for d (...)` loop (`[[ -d $d ]]`) — only existing dirs are prepended, including `~/.local/share/bob/nvim-bin`, `$HOME_DIR/zsh/bin`, `~/.local/bin`, `~/go/bin`, `~/.opencode/bin` — and `VISUAL`/`EDITOR`/`GIT_EDITOR` are resolved after it (nvim if on PATH, else vim).

**Zsh loading order** follows [unix.stackexchange.com/a/487889](https://unix.stackexchange.com/a/487889): `zshenv` (every shell: cheap static env only — no output, subprocesses, aliases or functions) → `zprofile` (login: PATH, tool config, then every `~/.zsh/private/*.zsh`, then rbenv shims + `RBENV_SHELL` written out statically instead of `eval "$(rbenv init -)"`, which cost ~60 ms per login mostly in a redundant `rbenv rehash` — the `rbenv` shell wrapper function lives in `zsh/ruby.sh`; PATH can't go in `zshenv` because macOS `/etc/zprofile` runs `path_helper` afterwards) → `zshrc` (interactive) → `zlogin` (login, shell fully set up: the `thisisfine.sh` banner + load time, only when interactive on a TTY outside Ghostty's quick terminal). No `zlogout` — nothing is acquired at login. `zshrc` sources `misc/utility.zsh`, then `commands.sh`, `git.sh`, `golang.sh`, `update.sh`, `overload.sh` (plus `ruby.sh` when `ruby` exists) and sets history options; only in interactive TTY sessions (`[[ -t 0 ]] && [[ -t 1 ]]`) does it continue with `ysu_ignored.sh` → `zim.sh` → `fzf.sh` → `bindkeys.sh` → `_after_zsh.sh`, plus carapace/vivid completion caches under `~/.cache/zsh` and the OrbStack init. `zim.sh` self-bootstraps zimfw into `~/.zim` and generates `~/.zim/init.zsh` from the linked `~/.zimrc`. Non-login interactive shells (e.g. nvim `:terminal`) inherit the login env and get no banner.

**Neovim plugin manager:** lazy.nvim is bootstrapped in `init.lua` if not present. Plugins are declared in `lua/plugins/` (24 spec files). The config disables several built-in nvim plugins for performance. LSP server configs in `lsp/` cover harper_ls, jsonls, lua_ls, ruby_lsp, yamlls. Neovide GUI config in `lua/neovide.lua` and `neovide.toml`.

**Neovim version management:** `bob` manages Neovim versions (config at `home/bob.json`, which sets `add_neovim_binary_to_path: false`); `zprofile` adds bob's install dir `~/.local/share/bob/nvim-bin` to PATH itself. The config pins `downloads_location` to `$HOME/.local/share/bob` because macOS's default bob data dir (`~/Library/Application Support/bob`) contains a space, which breaks neovim's Makefile when `enable_release_build` compiles nightly from source (unquoted `$(MAKEFILE_DIR)` in the `.ran-deps-cmake` recipe).

**Karabiner config pipeline:** deps live in `home/karabiner/node_modules` (`karabiner.ts`, `tsx`, `typescript`, `zod`, `bun-types`); the untracked `package.json`/`tsconfig.json` are missing from the tree (recoverable from dangling commit `d54e444` or `stash@{0}`), so call bun directly: `bun index.ts` → writes profile `New Goku` into Karabiner-Elements' live `~/.config/karabiner/karabiner.json`; `bun index.ts --dry-run` prints instead and also skips the `writeToGlobal()` call. `index.ts` monkey-patches `fs.writeFile` to serialize same-path writes and rename atomically, because `karabiner.ts` fires unawaited writes that race the Karabiner daemon's own rewrites. `bun run scripts/verify-ids.ts` cross-checks `apps.ts` bundle-id regexes against installed apps via `mdfind`/`mdls` (extraction inlined in the script). Karabiner `shell_command`s run without a login shell, so anything needing secrets/PATH must go through `private-env.ts`'s `withPrivateEnv()`, which sources `$HOME/.zsh/private/private.zsh` (= `$PRIVATE_FILE`); see `rules/pikatea.ts`.

**Conditional symlinks:** macOS-only items use `if: "[ \`uname\` = Darwin ]"` guards in `install.conf.yaml`: `~/iCloud`, `~/Vaults`, `home/zsh/private`, `~/.ssh`, `~/.gnupg`, `~/.gitconfig.local`, `~/.agents`, `~/.claude`, `~/.config/opencode`, `~/.omp/agent/config.yml`, `~/.config/Hammerspoon2` (+ its `watchers/screens.js`). Karabiner has no link at all — its config is generated in place.

**Brewfile size:** `Brewfile` declares 5 taps, 72 formulae, 56 casks, 43 `mas` (Mac App Store) apps, plus 1 cargo, 1 go, and 4 npm packages.

**Hammerspoon 2 (JS) automation:** HS2's `require()` wraps each module in an IIFE, so modules share helpers through `globalThis` (e.g. `globalThis.isDocked` in `utils.js`), and `hs.urlevent` handlers must be pinned to `globalThis` or the JSFunction is garbage-collected within ~60–90s. `hs.timer` handles need the same pinning: a module-scope handle loses its callback ~2s after load (`hs.timer: callback is not a function`, then the timer stops itself). `hs.ax`/`hs.usb` watcher bugs in HS2 ≤0.0.12 are gone: 0.0.13 replaced every `addWatcher(cb)` with node-style `on(event, cb)`/`off`/`once` (`hs.application`, `hs.audiodevice`, `hs.camera` — both `hs.camera.on(event, cb)` and per-camera `cam.on(fn)` — `hs.screen`, `hs.usb`, `hs.power`, …; `hs.ax.on(element, notification, listener)`), fixed the AX watcher (the old `HSAXModule.WatcherKey` hashed AXSwift's `UIElement` wrapper, whose `hash(into:)`/`hashValue` recurse, overflowing the stack with `EXC_BAD_ACCESS`, "Thread stack size exceeded") and rooted the watcher bridge closures. The config requires 0.0.13+: `watchers/mqtt.js` hooks `hs.ax.on()` (application element, `AXTitleChanged`) for Ghostty title changes, and `watchers/screens.js` uses `hs.usb.on('added'/'removed')`. Stateful actions are URL-dispatched from Karabiner: `hammerspoon2://layout?name=…` (window/Moom layout plus caffeine state) and `hammerspoon2://omnifocus` (per-app OmniFocus AppleScript chain). Hyper-key keystroke/media bindings live entirely in Karabiner (`home/karabiner/rules/hammerspoon-ports.ts`, `rules/media-keys.ts`). `caffeine.js` exposes `globalThis.caffeine.{enable,disable,toggle}` to `layout.js`; it does not keep the Mac awake itself — it sends hyper+7 (`hs.eventtap.keyStroke(["ctrl","cmd","shift","alt"], "7")`) for the app bound to that hotkey (its earlier `hs.power`/menubar implementation, using the `caffeine-on.pdf`/`caffeine-off.pdf` icons, is commented out in place).

**Obsidian Vaults:** Dotbot symlinks `~/Vaults` → `~/Library/Mobile Documents/iCloud~md~obsidian/Documents` on macOS.

**`md2pdf` / `md2html` / MDSS:** `home/bin/md2pdf` is the whole pipeline — pandoc → standalone HTML, then, unless `--html` is given, headless Chromium `--print-to-pdf`; `home/bin/md2html` is a front end that execs it with `--html`. Styling comes from mdss 2.1.0's published **bundle** build, vendored in `home/bin/mdss.css` (MIT, with the Google-Fonts `@import`s dropped so rendering never needs the network — the body serif falls through to Cambria, headings use the installed Fira Sans Condensed — plus a marked local additions block for `@page` geometry, pandoc's syntax classes and the TOC). `-c/--css` appends stylesheets after it; `-s/--stylesheet FILE` replaces it entirely (then the injected `@page` rule carries only the `-p`/`-m` values given explicitly, so the replacement's own page box wins by default — and since the template has no `$highlighting-css$`, code highlighting colours come only from that file). One file serves both outputs because the bundle wraps its screen rules in `@media screen` and its print rules in `@media print`: browsers get the 910px screen layout, and both browser printing and `--print-to-pdf` get the print rules, so printing `md2html` output reproduces the PDF `md2pdf` writes (verified byte-identical). pandoc renders through a minimal inline template, because the default standalone template ships a stylesheet that fights MDSS on body width, padding and colour; it also omits `$highlighting-css$`, so MDSS colours pandoc's `.kw`/`.co`/… spans instead of skylighting double-styling code. `--embed-resources` inlines CSS and images, which makes `md2html` and `--keep-html` output self-contained. mermaid fences (```` ```mermaid ````, ```` ```{.mermaid} ````, `::: {.mermaid}`) are detected by grepping the inputs; for those the script appends, before `</body>`, the vendored mermaid 11.17.2 (`home/bin/mermaid.min.js`, unmodified upstream, ~3.5MB) and a short script that first lifts the definition out of pandoc's `<code>` wrapper — mermaid parses the definition off the element itself and fails on that child element (`Syntax error in text`) until the text is moved up — then calls `mermaid.initialize`. The template must keep `$for(include-after)$` for `--include-after-body` to land at all: pandoc silently drops the option when the template omits the variable. The print step passes `--virtual-time-budget=15000` so async work (mermaid rendering) settles before Chromium prints. Page geometry is injected as an `@page` rule after the stylesheet (mdss.css carries the same defaults), since Chromium's `--print-to-pdf` takes no size flags. Headless Chromium on macOS writes the PDF and then never exits, so the script waits for the `bytes written to file` marker on its stderr and kills it (60s cap).
